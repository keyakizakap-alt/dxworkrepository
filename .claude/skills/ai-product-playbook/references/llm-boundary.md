# LLM の境界・失敗設計・コスト

## 1. 境界の引き方

```
入力検証 → ハードフィルタ → 分類 → 決定論的スコアリング → 重複検出
  → 不足検出 → 結論の確定
  ────────── ここまで LLM 不使用 ──────────
  → 確定済みの数点だけを LLM へ → 説明文生成 → 検証 → 不正なら決定論的説明
```

この形にすると、以下が**構造的に**保証される（テストではなく設計で保証する）。

- カタログ外・許可外のものが出力されない — LLM へは許可 ID のリストしか渡さず、
  返却された ID を照合し、1 つでも一致しなければ**出力ごと**破棄する
- 同じ入力から同じ結果が出る — スコアは純関数。同点時のタイブレークまで一意に決める
  （例：「安い順 → ID 昇順」）
- AI が落ちてもプロダクトが動く — 変わるのは説明文の書き方だけで、結論は変わらない
- 除外条件が必ず守られる — アレルギー等は減点ではなく**ハードフィルタ**

**検証方法**：モック LLM を通した場合と AI 無効の場合で、結論（商品 ID 列など）が
完全一致することを実行結果で確認する。「AI が変えるのは文章だけ」を実測で言えるようにする。

## 2. 責務の分離

| レイヤー | 置いてよいもの | 置いてはいけないもの |
|---|---|---|
| `components/` | 表示・入力 | 判断ロジック、スコア計算、API キー |
| `app/api/` | 入出力検証、オーケストレーション | スコア計算、選定 |
| `domain/` | 純粋な判断ロジック | LLM 呼び出し、`process.env`、DOM |
| `server/` | LLM 呼び出し、プロンプト | 選定、スコア変更 |
| `schemas/` | 型と検証 | ロジック |

`domain/` は Node でそのまま単体テストできる状態を保つ。ここが依存を持った時点で、
「AI を抜いても動く」が崩れる。

## 3. LLM 出力の検証段（すべて通ったものだけ採用）

```
HTTP 成功 → JSON として解釈できる → Zod スキーマに合う
  → ID がすべて許可リスト内 → 禁止表現を含まない → 採用
```

どこかで落ちたら決定論的応答へ。**失敗を隠さない** — `fallback` と `fallbackReason` を
画面の根拠パネルに出す。「なぜ簡素な説明になったか」が分かる方が信頼される。

## 4. 拒否（refusal）と障害への 3 層

1. **プロンプト補強** — 「あなたは分類者であり生成者ではない。分類することは加担を意味しない」
   の一文をトーン制約に入れる。題材の過激さと目的の混同による過剰拒否を追加コストゼロで減らす。
2. **自動フォールバック** — OpenAI 互換ルーターの `models` 配列で次点へフェイルオーバー。
   候補は**異なるベンダー**にする（同一ベンダーは同じ理由で連鎖的に拒否するため）。
3. **縮退運転** — 統合 1 リクエストが失敗したら N 個の個別リクエストへ分割して再試行。
   個別も失敗した分は安全側の既定値で埋める。通常は発火させない（統合の方が品質が高い）。

**ティア降格**：品質優先ティアが 5xx / 429 / タイムアウトなら、コスト優先ティアで 1 度だけ再試行。
4xx（認証・リクエスト誤り）では再試行しない — 同じ結果を繰り返し課金するだけ。

## 5. モデル切替はレジストリで

処理ごとに使うモデルを 1 ファイル（`models.ts`）に集約し、環境変数で上書きできるようにする。
コード変更なしでモデルを差し替えられる状態を保つ。

| 処理 | 性質 | モデルの選び方 |
|---|---|---|
| 核となる判定 | 品質が製品価値そのもの | 最上位モデル。ここをケチらない |
| 機械的な採点・写像 | 毎回・並列に走る | 安価な高速モデル |
| 疎通確認 | 生成しない | 認証確認のみ（`GET /models`）で費用ゼロ |

呼び出し口は `complete()` のような**共通口 1 つ**に集約する。デモ/ライブの切替、
ログ、費用計上をそこ 1 か所で効かせるため。

## 6. コスト管理（3 段構え）

| 手段 | 効果 |
|---|---|
| **呼ばない** | 判断は決定論的。LLM は説明文だけ |
| **二度課金しない** | 同じ問い合わせは応答をキャッシュ（例：30 分・最大 200 件、鍵はプロンプトの SHA-256） |
| **上限で止める** | 1 日の推定費用が上限に達したら外部呼び出しを停止し決定論的応答へ |

キャッシュが効くのは**選定が決定論的だから**。同じ条件から必ず同じプロンプトが生成される。

**費用は隠さず「推定」と明記する。** ルーターの `model=auto` では確定価格が分からないため、
モデル名から単価表を引き、不明ならティア既定値を使う。単価は環境変数で実請求に合わせられるようにする。

> この回の推定費用 約0.412円（実モデルの単価表からの推定値）

上限判定は**プライバシー判定と同じ関門**（`ai-policy.ts`）に載せる。外部へ出る経路が
1 つしかないので、費用の歯止めも 1 か所で効く。

## 7. ログに残すもの / 残さないもの

- 残す：リクエスト ID・タスク種別・選択モデル・応答時間・成否・スキーマ検証結果・
  フォールバック有無・推定トークン数
- 残さない：**入力本文**・氏名・顔写真・詳細な健康情報・API キー・IP

保存していなければ、漏洩も学習利用も起こりようがない。これが最も強い保証。
