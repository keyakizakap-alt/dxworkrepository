# リサーチと裏取り

対象領域は主に AWS / AI / LLM / Google Cloud / Azure / Databricks / ネットワーク技術。
変化が速いため、**自分の記憶を信用しない**ことが出発点。

## 手順

1. **調査範囲と目的を確認する** — 何を決めるための調査か。決定に効かない情報は集めない
2. **情報収集** — 公式ドキュメントを最優先で検索する
3. **複数ソースで裏取り** — 1 ソースで断定しない
4. **要点整理と出典明記**

## 必ず検索する（記憶で答えない）

- クラウドサービス（AWS / Azure / GCP）、Databricks、各種ライブラリの **API 仕様**
- **機能ステータス**（Preview / GA / 非推奨 / 廃止予定）— 公式の最新リリースノートまたは
  公式ドキュメントで裏取りする。バージョン番号と提供リージョンの差異にも注意する
- **料金・上限・モデル名** — 特に LLM 関連は改定が速い

## 出典の書き方

情報源には **取得日・URL・公式/非公式の別**を併記する。

- 公式ドキュメントを最優先
- 公式でなくても、一次情報・著名なエンジニアの技術記事・実績あるベンダー資料は採用してよい。
  ただし**出典の種別（公式か否か）を明示する**
- 情報が対立している場合は、公式か個人かに限らず**どちらがより信頼できるかを判断して選び、
  選んだ理由を書く**

## 断定と推測を混ぜない

推測・未検証・情報が古い可能性がある内容を含む場合は、必ずその旨を明示する。
「たぶん」で書いた行と、公式で確認した行が、同じ見た目で並んでいてはいけない。

## 生成 AI 業界の事例

**原則として直近 6 か月以内**のものに絞る。古い事例しか無い場合は、その旨を明示する
（「2024 年の事例しか見つからなかった」と書く）。

## 調べても分からなかったとき

分からなかったことを分からなかったと書く。それらしい答えで埋めない。
次に何を調べれば分かるか（誰に聞くか、どの一次情報を当たるか）まで示す。
