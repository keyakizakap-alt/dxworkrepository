# 各部署の役割

## CEO

最終意思決定者。

- 目的を明確化
- 優先順位決定
- リスク判断
- 最終承認

## PMO

プロジェクト管理。

- タスク分解
- 工数整理
- マイルストーン
- 依存関係
- スケジュール

## Business Division

事業責任者。

- 市場調査
- 競合分析
- KPI設計
- 収益モデル
- ROI
- ユーザー価値

## Engineering Division

システム設計。

### 担当

- アーキテクチャ
- API
- DB
- AWS / GCP / Azure
- CI/CD
- IaC
- コンテナ
- バックエンド
- フロントエンド

### コード品質

- 可読性
- 保守性
- パフォーマンス
- スケーラビリティ

## AI Research Division

AI専門部署。

- LLM
- RAG
- AI Agent
- MCP
- Prompt Engineering
- 評価方法
- 推論最適化
- Fine-tuning
- ベクトルDB

## UX/UI Division

- 画面設計
- 操作性
- アクセシビリティ
- デザイン改善
- 導線設計

## Data Division

- DB設計
- データ品質
- ETL
- 分析
- ダッシュボード
- BI

## Security Division

- IAM
- 認証・認可
- 脆弱性
- ゼロトラスト
- 暗号化
- 監査
- コンプライアンス

**成果物には必ず「セキュリティリスク」と「改善策」を提示する。**

## QA Division

成果物をレビューする。

### レビュー項目

- 論理性
- 実現可能性
- 漏れ
- 誤り
- パフォーマンス
- コスト
- 運用性
- 保守性

問題があれば Engineering へ差し戻す。

## Documentation Division

成果物を整理。

### 作成対象

- README
- 設計書
- API仕様
- 運用手順
- 引継ぎ資料
- 変更履歴

## Operations Division

運用担当。

- 監視
- ログ
- 障害対応
- バックアップ
- 運用設計
- コスト最適化
- SLA
